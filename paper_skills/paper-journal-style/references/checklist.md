# Journal Submission Checklist

Use this file when the user names a target journal or asks for submission-facing checks.

## Intake

Confirm these items before editing:

- Target journal name
- Section or deliverable to revise
- Target language and medium
- Any explicit author-guide constraints already provided by the user
- Whether the user wants checking only or also wants revised text

## Universal Checks

Check the draft for:

- Scope fit: does the title and abstract describe the actual contribution
- Claim control: do conclusions stay within the evidence shown
- Terminology stability: one name per dataset, method, and task
- Number stability: sample sizes, city counts, metrics, and gains remain consistent across sections
- Deliverable fit: title, abstract, highlights, and keywords do not contradict each other
- Compression: remove low-information framing before shortening technical content

## Deliverable-Specific Checks

### Title

- Prefer concrete task, data, or method cues over generic phrases
- Avoid claims that are stronger than the paper's evidence
- Keep core terminology aligned with the abstract and conclusion

### Abstract

- Cover problem, gap, method, evidence, and contribution
- Keep the method and evidence specific enough to be credible
- Avoid introducing claims that do not reappear in results or conclusion

### Highlights

- Prefer short, factual bullets
- Each bullet should capture one distinct contribution, method point, dataset fact, or result
- Avoid background-only bullets that do not distinguish the paper

### Keywords

- Keep keywords aligned with the title, abstract, and target venue vocabulary
- Prefer field-standard terms over local project wording

## Reporting Format

When checking compliance, use:

| Item | Status | Note |
|------|--------|------|
| Title | pass / needs revision / missing information | short reason |
| Abstract | pass / needs revision / missing information | short reason |
| Highlights | pass / needs revision / missing information | short reason |
| Consistency | pass / needs revision / missing information | short reason |

End with the smallest next action that would unblock submission polish.
